## Область изменений

Основные файлы: `js/week-scenarios.js`, `js/meta.js`, `js/events.js`, `index.html`.
Разрешённые сопутствующие изменения: `js/core.js` для чтения сохранённого `weekNumber`, `js/player.js` для его увеличения только после победной пятницы, отдельный тест `scripts/qa-plan-23.js`, записи по этой задаче в документации и реплики в `js/lines.js`; общие файлы — только в последовательном интеграционном слоте.
Уточнение области потока A: `js/core.js` и `js/player.js` необходимы, потому что единственное надёжное место для сохранения номера недели — постоянный `store`, а условие «только победная пятница» вычисляется в `finishGame()` после определения итогового исхода. `js/events.js` остаётся единственным планировщиком A03: он должен объединить его цель Маджикистана и дополнительные ID D5, не создавая второй очереди.
Фактические `DAYS` уже содержат цель `printReport` во вторник, тогда как D5-модель ожидает заменить другую цель на `printReport`. Точечная интеграционная поправка `js/week-scenarios.js`: если цель печати уже есть, оставить ровно её и не создавать дубликат; в четверг заменить доступную событийную цель Маджикистана.
Обнаруженное при проверке уточнение: `scripts/qa-plan-03.js` записывал wrapper вместо v3 snapshot в тест восстановления, из-за чего проверка случайно зависела от optional события СБ. Разрешена только тестовая правка fixture/ожидаемой длины; runtime карточки 03 не меняется.
Не вносить попутный рефакторинг.

## Шаги и правила

1. Первая неделя всегда текущая обучающая. После weekDone выбирать normal, reports, repairs циклически по сохранённому weekNumber; порядок воспроизводим.

2. reports: в ВТ/ЧТ одна существующая событийная цель заменяется на печать отчёта; по одному jam гарантировать не позже 15:00. repairs: в ВТ/ЧТ гарантировать internet/autoshka при доступном Сиргее, иначе jam.

3. Не менять кофе/перекуры/туалет/обед. Не включать недоступную механику до её unlock. Не добавлять сверх нормы вторую катастрофу, дополнительный daily или невыполнимый task.

4. Каждая тема меняет максимум 1 небытовую цель в указанные дни; остальные правила DAYS остаются. Один источник finalTasks/finalEventQueue после применения темы и 03.

5. Тексты баннера краткие: «Неделя отчётов» / «Неделя техработ». Сценарий сохраняется при reload и повторе дня.

6. План и частоту проверок пока не увеличивать: отдельная калибровка 34.
