## Шаги и правила

1. Предлагаемый API: makeSaveSnapshot(source), validateSaveSnapshot(raw), migrateSaveV2(raw); функции верхнего уровня, без обращения к DOM и localStorage.

2. Снимок содержит исходные показатели, seed генератора, очередь и таймер следующего события, полное JSON-состояние текущего события (включая work/watch/food), положение/действие/таймер игрока, состояние/таймеры Д.Н., runtime-поля коллег, временные бонусы, список задач, статистику и новый объект extensions.

3. Составить явные белые списки полей по фактическим объектам; не сериализовать DOM, функции, ссылки desk, изображения и пути с циклическими ссылками. Пути можно восстановить по целевой точке, сохранив состояние и назначение.

4. extensions содержит только JSON-поля модулей из CONTRACTS.md; отсутствующие поля получают нейтральные defaults. Номер схемы предложить 3, но перед реализацией проверить текущий.

5. Миграция v2 сохраняет монеты, покупки, достижения, время и показатели; для отсутствующих полей задаёт безопасное положение и единственную передышку восстановления, помеченную в снимке. Не выдаёт награды и не вызывает startEvent.

6. Невалидный снимок возвращает структурированный результат с причиной; нельзя превращать NaN в бесконечный план или удалять все ключи nepalsya.

## Проверяемая приёмка

- [ ] Круговой JSON-проход.
- [ ] старый v2.
- [ ] неизвестная версия.
- [ ] отрицательные/NaN показатели.
- [ ] неизвестный event id.
- [ ] снимок Маджикистана с work=3.
- [ ] отсутствие extensions. Исходный объект после вызова не изменён.
- [ ] Выполнены общие проверки из COMMON.md; новые игровые исходы проверены адресными сценариями.
- [ ] Обработаны новая смена, отмена, пауза, загрузка, конец смены и отсутствие зависимого NPC.
- [ ] Задача не меняет катастрофу Альджазиры, обязательную бытовую рутину и старые покупки.
- [ ] Результат соответствует описанию, а не только отсутствию исключений.
