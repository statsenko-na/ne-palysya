Основные файлы: `js/meta.js`, `js/events.js`, `js/config.js`.
Расширение scope потока A: `js/core.js` нужен, чтобы после restore сохранить гарантированную цель из старых v3 снимков, в которых поле ещё было пустым; `js/save-schema.js` валидирует deadline гарантированного события; `game.js` добавляет только диагностическое поле в существующий debug getter для адресного теста. Если нужен другой runtime-файл, сначала объяснить необходимость в handoff и обновить область карточки. Не вносить попутный рефакторинг.

## Шаги и правила

1. После выбора списка дел построить очередь событий. Таблица prerequisites: majik -> majik; остальные существующие цели сверить по LINES.dayTasks, не считать любое слово «отчёт» событием.

2. Если требуется majik, вставить ровно один majik первым допустимым событием после открытия механики, перед food; не увеличивать число обычных событий: вытеснить одно необязательное.

3. Обязательное событие имеет deadlineStart=15:00. По достижении дедлайна не ждать бесконечно idle начальника: событие majik допустимо параллельно его проверке, поскольку требует Excel. Активное другое событие не прерывать; резервировать окно заранее, не начинать длинное необязательное перед ним.

4. Обед и будущий daily откладывают событие; после возвращения обязательное получает приоритет. Сохранить очередь и флаг dispatched через 02.

5. Случайный добровольный ранний уход не обещает выполнение всех дел. Задачи «подставить соседа» и «пересидеть проверку» требуют проверки доступности нужного NPC/механики, но не автозавершения.

6. Не менять кофе/перекуры/туалет/обед и их количество.

## Проверяемая приёмка

- [ ] один детерминированный сценарий времени до дедлайна.
- [ ] reload до/после dispatch.
- [ ] ПН без событий.
- [ ] прохождение первой и следующих недель.
- [ ] Выполнены общие проверки из COMMON.md; новые игровые исходы проверены адресными сценариями.
- [ ] Обработаны новая смена, отмена, пауза, загрузка, конец смены и отсутствие зависимого NPC.
- [ ] Задача не меняет катастрофу Альджазиры, обязательную бытовую рутину и старые покупки.
- [ ] Результат соответствует описанию, а не только отсутствию исключений.
