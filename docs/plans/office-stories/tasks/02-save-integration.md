## Область изменений

Основные файлы: `js/core.js`, `js/meta.js`, `js/events.js`, `index.html`.
Расширение scope потока A: `js/autopilot.js` нужен для липкого `autoUsed`; `js/boss.js`, `js/interact.js` и `js/player.js` нужны, чтобы отложенные callbacks проверяли `shiftId`; `js/save-schema.js` нужна для безопасного сброса только повреждённого extension и сохранения его причины; `game.js` даёт адресным браузерным тестам диагностировать результат загрузки и безопасные точки. В `js/events.js` волны ухода при учениях, обеде и пятничном пиве используют сериализуемые игровые таймеры, иначе пауза/reload потеряли бы отложенное изменение `away`. Эти точечные причины зафиксированы в `handoffs/02.md`.
Разрешённые сопутствующие изменения: отдельный тест `scripts/qa-plan-02.js`, записи по этой задаче в документации и реплики в `js/lines.js`; общие файлы — только в последовательном интеграционном слоте.
Если нужен другой runtime-файл, сначала объяснить необходимость в handoff и обновить область карточки. Не вносить попутный рефакторинг.

## Шаги и правила

1. Подключить save-schema после core до meta; верхнеуровневый код модуля не вызывает ещё не объявленные игровые функции.

2. resetGame сначала создаёт defaults, затем применяет валидный снимок. После применения не перерисовывать RNG, смог, очередь событий и удалёнку случайными значениями.

3. Стартовые бонусы, в том числе лава-лампа, начислять только новой смене. Загрузка не повторяет сбор на ДР, катастрофу, награду события или выдачу монет.

4. Сохранить идентификатор shiftId, состояние autoUsed и флаг demo; demo не пишет прогресс. Поздние модули получают поля extensions только после своего подключения.

5. Убрать или защитить от старой смены отложенные setTimeout, которые меняют геймплей/away; использовать игровые таймеры либо проверку shiftId. Косметические старые реплики не должны запускать события.

6. Восстановить действие у корректной точки: work у SEAT, toilet внутри, queue в допустимом слоте. Внешние ссылки на coworker восстанавливать по id.

7. Ошибку отдельного расширения заменять его безопасным default с записью причины; не стирать весь прогресс. Ввести явный результат загрузки new/resumed/migrated для остальных модулей.
