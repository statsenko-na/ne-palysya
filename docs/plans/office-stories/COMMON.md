# Общие правила реализации

## Границы

Для запуска четырёх параллельных диалогов действует уточнение [parallel/PROTOCOL.md](parallel/PROTOCOL.md): один диалог выполняет назначенный блок, один PR на поток; B/C/D готовят модели, A подключает их. Это исключение из правила одной карточки ниже. Критерии поведения и проверки исходных карточек сохраняются.

Выполнять одну карточку. Не реализовывать соседнюю «заодно». Проверять зависимости, актуальный AGENTS.md и проектный office-game-dev.
Перед изменением игры прочитать docs/README.md, docs/GAMEPLAY.md, docs/ART_DIRECTION.md и нужные фрагменты кода.
Пути, функции и цифры карточек основаны на 0.24.1; если база изменилась, сверить их, записать расхождение. Не перетирать чужие изменения.

Код игры запускается через file:// без npm, сборки, внешней базы или сервера. Разрешены существующие инструменты разработки; в runtime не добавлять import/require/fetch для загрузки модулей.
Новые функции/переменные классических скриптов объявлять на верхнем уровне. Обёртки world/lines/art/config сохранить. Не создавать универсальный event bus или систему плагинов ради нескольких механик.

## Выполнение

1. Прочитать карточку, зависимости и handoff предшественников.
2. Проверить git status. Работать в отдельной ветке codex/plan-ID-короткое-имя; не переписывать историю и не удалять чужие изменения.
3. Написать короткий checklist конкретных пунктов карточки.
4. Реализовать сначала состояние и исходы, затем UI, сохранение и автопилот в пределах карточки.
5. Редактировать через apply_patch. Новые игровые реплики — js/lines.js, UI и документация по-русски.
6. Прогнать адресные проверки; проверить реальные Canvas-снимки, когда затронут визуал.
7. Обновить документы фактического поведения, CHANGELOG.md и VERSION.md по протоколу ORCHESTRATION.md.
8. Подготовить handoff и PR, не сливать его без соответствующей команды пользователя.

## Проверки

Для JavaScript после изменений:

```powershell
node --check game.js
Get-ChildItem -LiteralPath js -Filter *.js | ForEach-Object { node --check $_.FullName; if ($LASTEXITCODE -ne 0) { throw "Ошибка синтаксиса" } }
node scripts/qa.js
```

Проверить exit code каждого запуска, не продолжать считать тесты успешными после ошибки.
Чистые модели проверять отдельными scripts/qa-plan-ID.js через Node vm с загрузкой классического скрипта в контекст; не добавлять экспорт Node в runtime ради теста.
Целевые интеграционные тесты используют существующий scripts/pw.js и NP_DEBUG только в разрешённом debug-режиме. Не открывать debug API публично.
Сценарии должны проверять эффект (одна награда, корректный исход), а не просто наличие функций.

Обязательный scripts/qa.js уже включает автоматическую неделю. Это проектная проверка после изменения JS, не разрешение запускать дополнительные бот-смены, ручной плейтест или балансировочный автопилот. Для них нужна отдельная просьба пользователя.
Canvas-проверки можно делать постановкой конкретного состояния и снимком, без самостоятельного прохождения игры.

Для документационного PR без runtime-изменений: проверить ссылки, зависимости и git diff --check; запуск игры не нужен.

## Общие инварианты

- dt — симуляционные секунды, уже умноженные на timeScale главным циклом. Не умножать второй раз.
- Пауза останавливает геймплейные таймеры. Новые исходы не планировать через setTimeout.
- Изменять кайф через addFun и держать 0..100; отрицательный эффект не масштабировать бонусом среды/пятницы.
- Положительную работу добавлять через addWork; прямой штраф плану clamp >=0. Катастрофа Альджазиры остаётся прямым обнулением.
- Формальные выговоры через reprimand, пропуски через missAtDesk. Исключение существующего finishGame не размножать.
- Одна причина — один исход, в том числе если камера и начальник срабатывают в одном кадре.
- Логика не зависит от mute, FPS, размера окна, видимости телефона или языка клавиатуры.
- Время/состояние нового эффекта не меняются во время draw.
- Данные NPC связывать по id, а не индексу массива или имени.
- Отмена не равна завершению: не выдавать награды в общем endAction без проверки reason.
- Автопилот пользуется теми же эффектами, не получает иммунитет, мгновенное перемещение или бесплатные услуги.
- Демонстрационный режим не записывает новые рекорды и новые постоянные достижения плана; прежние demo-побочные эффекты перечислить отдельно, не чинить попутно весь проект.

## Окончание задачи

Нет скрытых TODO в активном пользовательском пути. Не показывать товар/кнопку/цель до подключения эффекта.
Если зависимость отсутствует, закончить независимую модель, не подменять её заглушкой в игровом релизе.
Сообщать конкретный блокер и готовые артефакты; не писать «готово», когда нет интеграции или не просмотрен изменённый Canvas.
