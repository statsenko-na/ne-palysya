# Четыре параллельных диалога

Этот режим заменяет «одна карточка — один диалог». Четыре диалога стартуют одновременно, каждый выполняет свою очередь. Общие файлы подключает только A.
Все изменения остаются в отдельных worktree и ветках. В исходной рабочей папке диалоги только читают план.

## Что сделать пользователю

1. Создать четыре диалога в этом же проекте и выбрать нужную модель.
2. Вставить в каждый его готовое сообщение из [COPY-PASTE.md](COPY-PASTE.md). Ничего дописывать про задачи не требуется.
3. Дождаться завершения основной волны B, C и D. Они выдадут ссылки на три draft PR.
4. Отправить A одно сообщение из раздела «Продолжение A», вставив эти три ссылки. A проверит пакеты, подключит всё и создаст общий PR.
5. Общий PR прислать на итоговое ревью. Слияние в основную ветку отдельно подтверждает пользователь.

Если A ещё работает над фундаментом, можно сразу прислать ссылки: это продолжение его задачи, а не отмена текущего этапа.
Если один поток исправляет ошибки, остальные продолжают свои независимые пакеты. Частично готовую ветку не выдавать за READY.

## Распределение

| Диалог | Последовательная работа | Результат |
| --- | --- | --- |
| [A](LANE-A.md) | Сохранения, фундамент, затем все подключения и интеграционные проверки | Один общий PR с работающими фичами |
| [B](LANE-B.md) | Очки → рекорды → оснащение → настройка эффектов | Четыре независимых пакета моделей |
| [C](LANE-C.md) | Отношения → йогурт → автошка → итоги недели/Тигран | Четыре независимых пакета моделей |
| [D](LANE-D.md) | Отвлечения → занятия → папка → память Д.Н. → темы недель | Пять независимых пакетов моделей |

A сначала делает 01 → 02 → 03 → 04 → 09, пока остальные готовят пакеты. Затем делает подключения по LANE-A.md.
Дейлики и групповой перекур — следующая волна в тех же диалогах после основной. Задача33 — резерв.

## Почему не четыре полностью независимых игровых PR

В существующей архитектуре большинство механик меняют один interact/player/events и общее сохранение. Разделение лишь по номерам создало бы конфликты и несовместимые состояния.
Поэтому параллелим основную логику, а применение эффектов, интерфейс и сохранение подключаем последовательно. Это не обещает четырёхкратного ускорения, зато убирает одновременную запись в общие файлы.
Три модельных PR — заготовки для A, не самостоятельные пользовательские релизы. В основной бранч их отдельно не сливать.
