# Поток A: фундамент, подключения и общий PR

Ветка codex/office-stories-a, отдельный managed worktree.
A — единственный исполнитель, который редактирует существующие runtime-файлы и подключает готовые модули. Производители B/C/D работают параллельно в своих worktree.

## Этап A0: подготовка

Прочитать PROTOCOL.md, API.md, исходные COMMON/CONTRACTS/BALANCE/REVIEW.
Создать или переиспользовать свой worktree от проверенного HEAD исходного проекта. Перенести незакоммиченный план по PROTOCOL.
Создать свой draft PR при возможности. Не изменять исходную общую рабочую папку.
Проверить граф задач и доступность среды тестов. Список требуемых модулей B/C/D не означает, что они уже существуют.

## Этап A1: пока работают остальные

Последовательно выполнить исходные задачи **01 → 02 → 03 → 04 → 09**, отдельный commit и handoff на каждую.
01 создаёт js/save-schema.js; остальные — реальные подключения и тесты по исходным карточкам.
09 остаётся инфраструктурой выбора без фиктивных игровых действий.
Никаких собственных реализаций js/moments/relationships/distractions и прочих файлов производителей.

После A1, если PR B/C/D ещё не переданы, выдать отчёт фундамента и точный запрос трёх ссылок. Не опрашивать их бесконечно и не ставить автоматизацию.
Можно завершить текущий ответ; тот же диалог продолжится после сообщения пользователя.

## Этап A2: приёмка пакетов

Пользователь передаёт PR B, C, D. Проверить:
- B: B1/B2/B3/B4;
- C: C1/C2/C3/C4;
- D: D1/D2/D3/D4/D5.
READY-манифест и HEAD SHA соответствуют PR; branch не меняется во время принятия.
Проверить только разрешённые файлы, сигнатуры, формы state/effects, адресные тесты. Влить зафиксированные commits в ветку A.
Если пакет неполон, не писать «готово»; продолжить только доступные адаптеры, сообщить блокер.

## Документация и релиз

На каждом включении актуализировать фактическую GAMEPLAY/ART_DIRECTION, накопительный changelog и VERSION в своей ветке. Согласовывать конечный номер версии от фактической базы, не заранее всем потокам.
Сохранить старые покупки/прогресс, добавлять migrations через01/02.
Весь объединённый код проходит node --check и scripts/qa.js плюс tests B/C/D и адаптерные проверки. Проверить Canvas.
PR A описывает работающие функции и отложенные пункты. Не сливать в main.
