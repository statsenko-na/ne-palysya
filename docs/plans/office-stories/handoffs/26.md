## Реализовано

- В меню доступно необязательное имя до 20 Unicode code points; пустое имя разрешено и в рекорде становится «Быкентий». Имя сохраняется как последнее введённое. На экране результата есть поле для следующего игрока, так что имена можно менять между сменами.
- Имя, сложность, ruleset и максимальная скорость времени фиксируются при новой смене. Совпавший сохранённый `runId` при продолжении сохраняет ту же запись; изменение последнего имени не переименовывает смену. `autoUsed` сохраняется при перезагрузке и не сбрасывается выключением автопилота.
- В `finishGame` после финального расчёта один раз добавляется исход `win`, `munich` или `fired`; повторный runId модель отвергает. В таблице показываются топ-10 и фильтры дня, сложности, ручной/автоматической игры. Имена создаются через `textContent`.
- `auto.demo` не меняет playerName, локальную таблицу и прежние best-ключи. Старый `best.<day>` импортируется отдельно как результат правил 0.24.1; `best.<ruleset>.<day>` сохраняется для существующего экрана оценки. Отрицательный итог передаётся B2 как 0, как требует контракт модели; игровой расчёт и показанные очки не меняются.
- Изменены: `index.html`, `style.css`, `game.js`, `js/meta.js`, `js/player.js`, `scripts/qa-plan-26.js`, `CHANGELOG.md`, `VERSION.md`, `docs/GAMEPLAY.md`, карточка 26 и handoffs.
- Версия `0.26.15`; все script/style cache-buster в `index.html` совпадают.

## Контракт

- Подключён B2 API из `js/records.js`: `normalizePlayerName`, `makeRecord`, `createLocalRecordsState`, `addLocalRecord`, `listLocalRecords`.
- Постоянные ключи хранилища: `nepalsya.playerName`, `nepalsya.localRecords`, `nepalsya.activeRecordIdentity`. Объект активной записи содержит `runId`, `name`, `dayIndex`, `difficulty`, `rulesetId`, `maxTimeScale`. Максимальная скорость только возрастает и переживает перезагрузку.
- Объект активной записи захватывается после `loadSavedProgress()`: при продолжении смены восстанавливается совпадающий `runId`; новая или несовместимая смена фиксирует текущее имя и игровой контекст. Старые сохранения без объекта активной записи получают имя из последнего поля при первом старте этой версии. После добавления исхода объект очищается.
- Новая snapshot-схема и migration не добавлялись. Порядок script-тегов: `js/records.js` после `js/week-outcomes.js`, перед `js/meta.js`.
- Баланс и игровые очки не менялись; demo и обычный результат по-прежнему используют прежние расчёты.
