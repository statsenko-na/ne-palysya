# D5 — сценарии повторной недели

Статус: модель готова к подключению; календарь, задачи и очередь событий игры не менялись.

## API и состояние

- selectWeekScenario({weekDone, weekNumber}) возвращает deterministic DTO scenario/active/banner. weekNumber трактуется как число победных пятниц: 0 пока первая неделя не завершена; после weekDone номера 1/2/3 дают normal/reports/repairs, затем цикл повторяется. До weekDone возвращается normal с active=false.
- applyWeekScenario(scenario, baseTasks, baseEvents, context) возвращает копии tasks/events, requiredEventIds, eventDeadlineMinutes и replacedTaskId. Входные массивы не мутируются. Можно передать строковый id сценария или результат selectWeekScenario; во втором случае контекст проверяется на совпадение недели.
- Общий context: weekDone, weekNumber, dayIndex 0..4, unlockedEventIds. Модель меняет только вторник (1) и четверг (3), не бытовые задачи.
- reports заменяет ровно один выбранный через replaceableTaskIds существующий небытовой event-goal на printReport; для object task интегратор передаёт канонический reportTask из LINES. В эти дни выдаёт requiredEventIds=['jam'] и eventDeadlineMinutes.jam=900 (15:00) для единственного планировщика A03.
- repairs: вторник требует internet, если оно разблокировано, иначе jam; четверг при доступном Сиргее требует autoshka, с fallback на internet, если он разблокирован, иначе jam. Без доступного Сиргея в четверг требуется jam. Другие события и цели не добавляются; для четверга context требует sergeyAvailable.
- Если событие закрыто/unlocked id отсутствует или нет выбранной цели отчёта, модель безопасно возвращает отказ и исходные массивы.
- Повтор дня/reload детерминированы, пока адаптер сохраняет weekNumber; значение следует увеличивать только на победной пятнице.
