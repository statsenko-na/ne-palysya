## Реализовано

- Новый отдельный каталог: `thermos` — 18, `mirror` — 18, `autoclicker` — 30 KPI-коинов. Старые `UPGRADES` и покупки кресла/турки/прочего не читаются и не меняются.
- Покупка списывает переданный баланс атомарно; loadout содержит два уникальных слота. Изменение покупки/экипировки требует `phase: 'menu'|'ended'`; активная смена держит снимок `activeLoadout`.
- Заряд термоса появляется после первой полной личной чашки в смену, кофе Хладу его не даёт. Использование через телефон возвращает `coffeeBoost = max(currentBoost, 8)`, расходует один заряд и не возвращает работу, кайф, задачу кофе или статистику.
- Зеркало доступно только из активного loadout, у стола, при `distance <= 180` и прямой `lineOfSight`. Текущий инсайд Хлада показывает время до следующей проверки, а не направление; зеркало даёт отдельную информацию, не заменяет и не дублирует этот таймер. Угол стрелки вычисляет интегратор по своим координатам.
- Автокликер хранит 2 секунды установки и 10 секунд работы. Он может один раз задержать одну проверку пустого стола на 2 секунды по `inspectionId`; возврат в настоящий Excel до срока даёт исход обычной проверки, истечение сигнала один `missAtDesk` для адаптера. Модель сама не вызывает выговор и не добавляет план/кайф/рабочее время/заявки. Дополнительный `inspectionResolved` сигнал очищает ожидание, если проверку уже разрешил существующий прямой или камерный исход, чтобы не добавить второй промах.
- Изменённые файлы: `js/equipment.js`, `scripts/qa-parallel-b3.js`, этот handoff. UI, store, скрипт-подключение, рисунки и проверки камер остаются у A.

## Контракт

- `createEquipmentState(raw?)` → JSON state: `{ version, ownedEquipment, loadout:[id|null,id|null], activeLoadout:null|ids, shiftId, usedCharges:{thermos,autoclicker}, thermosCharge, thermosBrewed, thermosBrewSourceId, autoclicker:{phase,installRemaining,activeRemaining,placementUsed,waitUsed,inspectionWait,seenInspectionIds} }`. Пустые/старые данные получают пустые новые покупки и слоты; прежние апгрейды не мигрируют.
- `validateLoadout(state)` → `{ ok, valid, errors, reason }`.
- `purchaseEquipment(state,id,coins,{phase})` → `{ ok,state,coins,purchasedId?,reason }`; `coins` конечны и неотрицательны. Повторная покупка отказывает без списания.
- `equipItem(state,id,slot,{phase})` → `{ ok,state,slot?,reason }`; `slot` — 0 или 1. Чтобы поставить третий предмет, адаптер явно выбирает заменяемый слот.
- `beginEquipmentShift(state,{shiftId,newShift:true})` фиксирует `activeLoadout` и сбрасывает дневные заряды; `{shiftId,resume:true}` сохраняет снимок, таймеры и заряды. Повторный start с тем же shiftId идемпотентен.
- `recordThermosBrew(state,{brewId,completed,coffeeForColleague,paused,shiftEnded})` → state transition/chargeStored. `brewId` уникален, только полное личное приготовление.
- `useThermos(state,{currentBoost,viaPhone,paused,shiftEnded})` → state transition и `coffeeBoost`; контекст телефона и конечный текущий boost обязательны.
- `equipmentMirrorVisible(state,{atDesk,distance,lineOfSight})` → boolean. Модель возвращает только факт видимости; она не строит направление, LOS, карту или таймер.
- `activateAutoclicker(state,{atDesk,paused,shiftEnded})` запускает установку и сразу расходует одно применение смены.
- `beginAutoclickerInspection(state,{inspectionId,emptyDesk,paused,shiftEnded})` возвращает `{ ok,state,waitSeconds:2,inspectionId,reason }` только для активного устройства и одной проверки.
- `tickEquipment(state,{dt,paused,installationInterrupted?,inspectionId?,returnedToExcel?,inspectionResolved?})` продвигает только собственные симуляционные таймеры. `inspectionOutcome` бывает `passed`, `missAtDesk`, `resolvedElsewhere` или `null`; результат и state интегратор применяет атомарно. Для `missAtDesk` A вызывает существующую процедуру ровно один раз. `inspectionResolved:true` означает, что другой текущий исход уже был применён. Пауза таймеры останавливает.
- Пример: полная чашка создаёт один `thermosCharge`; `useThermos(...currentBoost:12...)` вернёт `coffeeBoost:12`. Неэквипированный автокликер либо повторная проверка с новым `inspectionId` возвращает отказ и не продлевает срок.
- Порядок script-тега: после `js/core.js` и до первого вызова; подключает только A. До того товар и эффекты не доступны игроку.

## Риски и продолжение

- Каталог — данные чистой модели, не UI. Не показывать товары до подключения их эффектов задач 20/21; старый магазин остаётся отдельным.
- Для сохранения A помещает объект состояния в `extensions.equipment`; при новом shift вызывает `beginEquipmentShift`, при resume передаёт прежний `shiftId`.
- Расхождений API.md нет. Дополнительный контекст `inspectionResolved` нужен для единственного исхода при уже применённом прямом/камерном обнаружении.
- Предлагаемая запись при интеграции: таблица двух слотов и ограничений предметов; артовая процедура не нужна до подключения товара.
