## Реализовано

- Нормализация имени: Unicode code points, удаление управляющих символов, схлопывание пробелов, лимит 20 code points, пустое имя становится «Быкентий». HTML-подобная строка остаётся обычным текстом; UI должен выводить её через `textContent`.
- Валидация результата смены без `Date.now`, `localStorage`, сети и персональных данных. Demo не записывается; `autoUsed`, сложность и ruleset разделены.
- Повторный `runId` игнорируется. Победы сортируются по score по убыванию, затем по времени по возрастанию; записи поражений идут после побед. Лимит — 10 строк на категорию (`difficulty + rulesetId + manual/assisted`) и 300 всего.
- Повреждённые строки и дубли при восстановлении отбрасываются; валидные сохраняются. Старые `best.day` передаются отдельно как `legacyBest`, получают подпись «Старый рекорд, правила 0.24.1» и не получают нового имени.
- Изменённые файлы: `js/records.js`, `scripts/qa-parallel-b2.js`, этот handoff. Модуль не подключён в игре и не меняет хранилище.

## Контракт

- `normalizePlayerName(raw)` → строка. Нестрочный ввод безопасно превращается в пустое имя по умолчанию.
- `makeRecord(input)` → `{ ok, record, reason }`. Обязательные поля: `runId`, `score`, `dayIndex` (0..4), `difficulty` (`easy|normal|hard`), `rulesetId`, `autoUsed` (boolean), `maxTimeScale` (0.5..3), `completedAt` (конечное число от 0), `outcome` (`win|munich|fired`). `name` — строка или пропущенное поле; `mode: 'demo'`, `demo: true`, `isDemo: true` отклоняются.
- `createLocalRecordsState(raw?)` → `{ version: 1, records, legacyBest }`; helper строит/очищает JSON-состояние. Старые результаты можно передать как `legacyBest: [{ dayIndex, score }]` или объект ключей `best.0`…`best.4`.
- `addLocalRecord(state, recordOrMakeRecordResult)` → `{ ok, state, record, reason }`. Дубликат возвращает `ok: false`, `reason: 'duplicate_run'`, прежнее состояние.
- `listLocalRecords(state, filter?)` → `{ ok, records, legacyBest, reason }`; filter принимает `difficulty`, `rulesetId`, `autoUsed`, `dayIndex`, `outcome`, `limit`.
- Пример: `makeRecord({ runId: 'shift-1', name: 'Алия', score: 90, dayIndex: 0, difficulty: 'normal', rulesetId: 'office-stories-v1', autoUsed: false, maxTimeScale: 1, completedAt: 1000, outcome: 'win' })` возвращает валидный DTO; повторная вставка того же `runId` возвращает отказ и не меняет массив.
- Хранилище остаётся отдельным постоянным ключом у A. API не делает миграцию сам: адаптер читает старые `best.day`, передаёт их в `legacyBest` и сохраняет новый JSON отдельно.
