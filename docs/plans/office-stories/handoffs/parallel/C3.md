# C3 — выбор помощи при автошке

Статус: модель готова к подключению. Исходная задача 18 не подключена к событию в игре.

## Изменения и проверка

- `js/event-autoshka.js` — машина состояния помощи с повторной проверкой времени события и отдельным pending штрафом быстрого решения.
- `scripts/qa-parallel-c3.js` — проверки 3/6 секунд, прерывания, ухода события, Сиргея away, паузы, обеда, reload и однократного −6 plan.
- Проверки: `node --check game.js`, синтаксис всех `js/*.js`, `node scripts/qa-parallel-c3.js`, `node scripts/qa.js` — пройдены; проектный QA — 89/89.

## Фактический API

- `createAutoshkaChoice({ eventActive, eventId, eventRemaining, sirgeyAvailable, playerAtDesk, legalAway, clockMinutes })` — возвращает `{ ok, state, effects, reason }`. State содержит разрешённые варианты: `reliable` при остатке не меньше 6 секунд, `quick` при остатке не меньше 3 секунд.
- `startAutoshkaRepair(state, branch, context)` — повторно проверяет тот же `eventId`, доступность Сиргея, позицию игрока, легальное отсутствие и остаток времени; `branch` — `reliable` или `quick`.
- `tickAutoshkaRepair(state, context)` — в `repairing` требует `dt`, `paused`, `eventActive`, `eventId`, `eventRemaining`, `sirgeyAvailable`, `playerAtDesk`, `legalAway`, `shiftEnded`, `clockMinutes`. `eventRemaining` — секунды события до этого шага, а `dt` — симуляционные секунды шага. Если событие закончится раньше нужного времени, ремонт отменяется без награды. Успешная ветка `reliable` выдаёт `addWork(6)`, помощь отношениям Сиргея и момент `colleagueHelp`; `quick` сразу выдаёт `addWork(3)` и сохраняет failure timer на 12 секунд.
- `tickAutoshkaRepair` для завершённой ветки `quick` требует `dt`, `paused`, `legalAway`, `shiftEnded`, `clockMinutes`. Таймер идёт независимо от базового события и во время легального отсутствия; уже наступивший штраф ждёт возвращения и паузы. Затем однократно выдаются `subtractWork(6)` и `message`.
- `cancelAutoshkaRepair(state, reason?)` отменяет только выбор/текущий ремонт без эффектов; завершённый исход не переключается.

Успешные и отменённые результаты не мутируют вход. Все эффект ID основаны на стабильном `eventId`. Модель не начисляет кайф: адаптеру нужно подавить обычный бонус chat для этой помощи и применить риск как у chat. `subtractWork` ограничивает снизу адаптер согласно API.

Если смена завершилась до истечения 12 секунд, ещё не наступивший pending штраф помечается `discarded`; если таймер уже истёк, штраф применяется даже при финализации, чтобы не потерять due effect. Это граничное правило зафиксировано в тесте; исходная карточка не уточняла поведение для смены, закончившейся раньше таймера.

## Пример

```js
const choice = createAutoshkaChoice({
  eventActive: true, eventId: 'shift-18:autoshka:1', eventRemaining: 18,
  sirgeyAvailable: true, playerAtDesk: true, legalAway: false, clockMinutes: 800,
});
const started = startAutoshkaRepair(choice.state, 'quick', {
  eventActive: true, eventId: 'shift-18:autoshka:1', eventRemaining: 18,
  sirgeyAvailable: true, playerAtDesk: true, legalAway: false, clockMinutes: 800,
});
// Если тот же eventId останется активен 3 секунды, tick выдаст только addWork(3).
```

Предлагаемая строка для `js/lines.js`: `autoshka.quick_failure` — Сиргей: «Костыль отвалился. Уже починили?»

## Интеграционные заметки

A оставляет существующее отвлечение Д.Н. при отказе от помощи, подключает активность как chat по палеву и положительным эффектам, учитывает ошибку `consumeFavor` при атомарном адаптере отношений. Здесь нет обращения к C1 или обновления существующего `officeEvent`; этот модуль не создаёт базовое событие и не редактирует старые перки.
