# План: разбить `game.js` на файлы по разделам

Инструкция для исполнителя (в том числе небольшой модели). Делай **строго по шагам**, после каждого шага — проверки и коммит. Ничего не придумывай сверх написанного.

## Цель

`game.js` — около 3950 строк в одном файле. Нужно разложить его на 9 файлов по уже существующим разделам (`// ---------- НАЗВАНИЕ ----------`), **не меняя ни одной строки логики**. Игра должна работать ровно как раньше, автотест — проходить так же.

## Почему это можно сделать почти механически

Сейчас весь `game.js` обёрнут в `(() => { 'use strict'; … })();`. Из-за обёртки все переменные (`mode`, `boss`, `player`, `day`, `fun`…) видны только внутри одного файла — поэтому кажется, что без большой переделки «общего состояния» его не разрезать.

Но у **обычных** (не `type="module"`) скриптов есть свойство: переменные `let` / `const` и функции `function`, объявленные **на верхнем уровне** файла без обёртки, видны во всех скриптах, подключённых на той же странице. Значит:

1. снимаем обёртку `(() => { … })();` → все объявления становятся общими для страницы;
2. режем файл по разделам на несколько файлов и подключаем их в `index.html` в **том же порядке**;
3. код продолжает видеть те же имена — переименовывать ничего не надо.

Проверено заранее:

- ни одно из ~330 верхнеуровневых имён `game.js` не совпадает со свойствами `window` (иначе был бы `SyntaxError`);
- все вызовы, которые выполняются **при загрузке** (не внутри функций), находятся либо в первом разделе (до «МАГАЗИН АПГРЕЙДОВ») рядом с тем, что они вызывают, либо в последнем разделе («ОБРАБОТЧИКИ» до конца файла). Поэтому порядок файлов = порядок разделов безопасен.

Почему **не** другие способы:

- `type="module"` / `import` — не работает при открытии `index.html` двойным щелчком (`file://`), а это обязательное правило проекта (`AGENTS.md`);
- собрать всё состояние в один объект `state.mode`, `state.boss`… — это тысячи правок вручную, слабая модель наделает ошибок;
- сборщик (webpack/vite/npm) — запрещён правилами проекта.

## Жёсткие правила

1. **Не менять логику.** Нельзя переименовывать переменные и функции, менять порядок строк внутри раздела, «улучшать» код, форматировать.
2. **Не оборачивать** новые файлы в `(() => { … })()` и не писать `export` / `import` / `type="module"` — это сломает общую видимость.
3. В начале **каждого** нового файла — строка `'use strict';`.
4. Порядок `<script>` в `index.html` = порядок файлов в таблице ниже.
5. Один шаг = один коммит. Если шаг не получился — откати его: `git checkout -- .` и начни шаг заново.
6. Не трогай `js/world.js`, `js/lines.js`, `js/art.js`, `js/config.js` — они уже отдельные.
7. Сообщения коммитов, комментарии и документация — на русском.

## Карта разбиения

Границы — это строки-заголовки разделов в `game.js` (ищи их поиском, номера строк могут сдвинуться). Файл начинается с заголовка и идёт до следующего заголовка из **этой** таблицы.

| № | Новый файл | Разделы (с заголовка … до заголовка следующей строки таблицы) | Что внутри |
| --- | --- | --- | --- |
| 1 | `js/core.js` | с начала файла … до `МАГАЗИН АПГРЕЙДОВ` | холст, картинки, `NP_CONFIG`, хранилище и сохранения, ввод (раскладки), звук, музыка, DOM, утилиты, коллизии, навигация, состояние |
| 2 | `js/meta.js` | `МАГАЗИН АПГРЕЙДОВ`, `ОНБОРДИНГ «КАК ИГРАТЬ»` | магазин, слайды «Как играть», задачи дня |
| 3 | `js/events.js` | `ОФИСНЫЕ СОБЫТИЯ`, `КАМЕРЫ СБ`, `ОБЕД, ТУАЛЕТ, ПЯТНИЧНОЕ ПИВО` | события дня |

Зачем: в автотесте есть проверки, которые ждут **реальное** время (`page.waitForTimeout`) и изредка падают сами по себе. Если их не починить, ты не отличишь свою ошибку от случайного сбоя.

2. Прогон до изменений, чтобы знать исходное состояние:

3. Почини проверку «болтовня даёт бонус» в `scripts/qa.js`. Найди блок:
   ```js
   // 8. Болтовня с коллегой
   await page.evaluate(() => { NP_DEBUG.setBoss(706, 446, 'office'); NP_DEBUG.teleport(520, 222); });
   await page.keyboard.press('KeyE');
   st = await page.evaluate(() => NP_DEBUG.state);
   check('болтовня стартует', st.player.action === 'chat', st.player.action);
   await page.waitForTimeout(3800);

   await page.waitForTimeout(3200);

   ```
   Замени **две** строки `await page.waitForTimeout(3800);` и `await page.waitForTimeout(3200);` на:
   ```js
   await page.evaluate(() => { NP_DEBUG.set({ noPee: true }); NP_DEBUG.skip(3.3); });
   ```

   ```bash

   ```

5. Коммит: `test: детерминированная проверка болтовни`.

## Шаг 1. Снять обёртку с `game.js`

Зачем: после этого все объявления `game.js` станут видны другим скриптам. Логика не меняется.

1. Открой `game.js`. Первые строки сейчас такие:
   ```js
   // «Не пались» — игровой цикл, механики, ИИ начальника и рендер персонажей.
   // Геометрия — js/world.js, баланс и неделя — js/config.js, арт офиса — js/art.js, реплики — js/lines.js.
   (() => {
     'use strict';
   ```
   Удали строку `(() => {`. Строку `  'use strict';` перенеси в самое начало файла (строка 1) без отступа: `'use strict';`.
2. Последняя строка файла — `})();`. Удали её.
3. **Не убирай** отступ в 2 пробела у остального кода — это лишний огромный diff. Отступ ни на что не влияет.
4. Проверки:
   ```bash
   node --check game.js
   node scripts/qa.js
   ```
   Должно быть `89/89` и пройдена проверка «нет ошибок в консоли».
5. Ручная проверка: открой `index.html` двойным щелчком, нажми «Выйти на смену», походи WASD, нажми E у своего стола — Быкентий садится в Excel. Открой консоль браузера (F12) — красных ошибок быть не должно.
6. Если появилась ошибка `SyntaxError: Identifier 'X' has already been declared` — какое-то имя из `game.js` совпало с глобальным именем. Не переименовывай сам — остановись и сообщи, какое имя.
7. Коммит: `refactor: game.js без обёртки IIFE (подготовка к разбиению)`.

## Шаг 2. Разрезать файл скриптом

Зачем: резать руками 4000 строк — легко потерять или задвоить кусок. Скрипт режет точно по заголовкам.

1. Создай **вне репозитория** (например во временной папке) файл `split.js` со следующим содержимым и запусти его из корня проекта: `node путь/к/split.js`.
   ```js
   // Разрезает game.js по заголовкам разделов. Запускать из корня репозитория.
   const fs = require('fs');
   const src = fs.readFileSync('game.js', 'utf8');
   const eol = src.includes('\r\n') ? '\r\n' : '\n';
   const lines = src.split(/\r?\n/);
   // [файл, заголовок раздела, с которого файл начинается]; первый файл — с начала game.js
   const PARTS = [
     ['js/core.js', null],
     ['js/meta.js', 'МАГАЗИН АПГРЕЙДОВ'],
     ['js/events.js', 'ОФИСНЫЕ СОБЫТИЯ'],
     ['js/interact.js', 'ВЗАИМОДЕЙСТВИЯ'],
     ['js/boss.js', 'ИИ НАЧАЛЬНИКА'],
     ['js/autopilot.js', 'АВТОПИЛОТ'],
     ['js/player.js', 'ИГРОК'],
     ['js/render.js', 'РЕНДЕР'],
     ['game.js', 'ОБРАБОТЧИКИ'],
   ];
   const starts = PARTS.map(([file, title]) => {
     if (!title) return 0;
     const i = lines.findIndex(l => l.trim() === `// ---------- ${title} ----------`);
     if (i < 0) throw new Error('Не найден заголовок: ' + title);
     return i;
   });
   for (let k = 1; k < starts.length; k++) if (starts[k] <= starts[k - 1]) throw new Error('Заголовки не по порядку: ' + PARTS[k][1]);
   const DESC = {
     'js/core.js': 'холст, картинки, баланс из NP_CONFIG, сохранения, ввод, звук, музыка, утилиты, коллизии, навигация, состояние',
     'js/meta.js': 'магазин апгрейдов, онбординг «Как играть», задачи дня',
     'js/events.js': 'офисные события, камеры СБ, обед, туалет, пятничное пиво',
     'js/interact.js': 'взаимодействия по E, достижения',
     'js/boss.js': 'ИИ Директора Начальниковича, план на день, выговоры',
     'js/autopilot.js': 'автопилот',
     'js/player.js': 'игрок и главный цикл обновления update()',
     'js/render.js': 'отрисовка, масштаб интерфейса, HUD, телефон, баннеры',
     'game.js': 'обработчики ввода и кнопок, NP_DEBUG, запуск игры',
   };
   let total = 0;
   PARTS.forEach(([file], k) => {
     let body = lines.slice(starts[k], k + 1 < starts.length ? starts[k + 1] : lines.length);
     if (k === 0) body = body.filter(l => l.trim() !== "'use strict';" && !l.startsWith('// «Не пались»') && !l.startsWith('// Геометрия —'));
     total += body.length;
     const head = [
       "'use strict';",
       `// «Не пались» — ${DESC[file]}.`,
       '// Общие переменные и функции объявлены на верхнем уровне и видны из других скриптов игры (без обёртки и модулей).',
       '// Порядок подключения — в index.html; см. docs/PLAN_SPLIT_GAME_JS.md.',
       '',
     ];
     fs.writeFileSync(file, head.concat(body).join(eol).replace(/(\r?\n)+$/, '') + eol);
     console.log(file, body.length, 'строк');
   });
   console.log('Всего строк кода:', total, 'из', lines.length);
   ```
2. Скрипт должен напечатать 9 файлов и «Всего строк кода» примерно равное исходному (разница — 3–4 строки шапки, которые он выбросил). Если выдал ошибку «Не найден заголовок» — **не правь** `game.js`, сообщи, какой заголовок не найден.
3. Проверь, что ничего не потерялось: в сумме функций должно быть столько же.
   ```bash
   git show HEAD:game.js | grep -c "function "
   cat js/core.js js/meta.js js/events.js js/interact.js js/boss.js js/autopilot.js js/player.js js/render.js game.js | grep -c "function "
   ```
   Два числа должны совпасть.

## Шаг 4. Проверки и починка ошибок загрузки

1. Синтаксис каждого файла:
   ```bash
   for f in game.js js/*.js; do node --check "$f" || echo "ОШИБКА в $f"; done
   ```
2. Автотест:
   ```bash
   node scripts/qa.js
   ```
3. Если есть ошибка при **загрузке** страницы (проверка «нет ошибок в консоли» или сразу всё падает), она будет одного из видов:
   - `ReferenceError: X is not defined`;
   - `ReferenceError: Cannot access 'X' before initialization`.

   Что это значит: какая-то строка **вне функций** (выполняется сразу при загрузке) использует `X`, который объявлен в файле, подключённом **позже**. Как чинить:
   - найди файл, где объявлен `X`: `grep -n "X" js/*.js game.js` (подставь имя);
   - найди строку вне функций (отступ 2 пробела, не начинается с `const`/`let`/`function`), которая вызывает `X` при загрузке;
   - **перенеси эту одну строку** в конец раздела запуска в `game.js` (перед строкой `if (location.hash === '#play' …`). Саму `X` не трогай.

   Ошибки внутри функций (например, при нажатии E) этим способом **не** возникают: к моменту нажатия все файлы уже загружены.
4. Повтори автотест 3 раза — каждый раз `89/89`.
5. Скриншоты на разных экранах:
   ```bash
   node scripts/screens.js
   ```
   Открой картинки из `.qa/screens/` и `.qa/` и сравни с тем, что было до изменений: меню, игра, телефон, финальный экран должны выглядеть так же.
6. Ручная проверка (5 минут): открой `index.html` двойным щелчком, сыграй начало смены: стол и Excel (E), кофе, телефон (Tab), пауза (P), автопилот (O), магазин (U в меню), «Как играть» (I), «⌨ Клавиши». Консоль (F12) — без красных ошибок.

## Известные последствия (это нормально)

- Переменные игры теперь видны из консоли браузера по имени (например `fun = 100`). Для одиночной офлайн-игры это не проблема; `NP_DEBUG` по-прежнему создаётся только под автотестом или с `?debug`.
- Файлы связаны через общие имена: если в будущем добавляешь переменную, объявляй её на верхнем уровне нужного файла и помни, что код, выполняемый **при загрузке**, может использовать только то, что объявлено в этом или более ранних файлах.
