# OpenAI и Codex: правила для этого проекта

Дата сверки официальных материалов: `2026-09-24`.

Игра запускается полностью локально, не вызывает OpenAI API и не содержит промпта модели. Этот документ описывает работу будущих Codex-агентов с кодом и документацией проекта.

## Принципы агентских инструкций

- Держи корневой `AGENTS.md` коротким и предметным: правила проекта, важные ограничения, расположение источников истины и необходимые проверки.
- Подключай подробный документ только к соответствующему типу задачи: `GAMEPLAY.md` для механик, `ART_DIRECTION.md` для визуала, этот файл для работы Codex/OpenAI.
- Не дублируй полные описания игры и сценарии в `AGENTS.md`. Устраняй устаревшие или противоречивые требования, а не наслаивай новые правила поверх старых.
- Оставляй повторяемые узкие процедуры в отдельном workflow/skill, если он реально нужен; не создавай универсальные инструкции с чрезмерно широкими триггерами.
- Не закрепляй в документации проекта имя «текущей» модели, модельный алиас или reasoning effort. Эта браузерная игра не использует модель, а текущая сессия Codex и доступность API-моделей могут различаться.

OpenAI рекомендует регулярно пересматривать `AGENTS.md`, избегать обязательного чтения нерелевантного набора документов, делать описания skills конкретными и раскрывать дополнительные инструкции только по мере необходимости. Это помогает не перегружать контекст и не привязывать репозиторий к поведению одной модели.

## Как формулировать задачу агенту

Пиши коротко и проверяемо:

1. **Цель:** что должно измениться для игрока или разработчика.
2. **Контекст:** какие уже существующие файлы и механики относятся к задаче.
3. **Ограничения:** что должно остаться совместимым и какие действия вне задачи.
4. **Готово, когда:** наблюдаемые критерии результата.
5. **Проверка:** подходящие команды и ручной сценарий.
6. **Документация:** какие MD-файлы требуется синхронизировать.

Сначала опиши требуемый результат, затем дай необходимые детали и примеры. Добавляй примеры только для важных форматов или неоднозначных случаев. Не переписывай содержимое проектных документов в каждый запрос.

## Работа с модельно-зависимыми рекомендациями

Если пользователь просит настроить промпт под конкретную модель или подключить API:

1. Уточни точное имя модели и продуктовый контекст — Codex, API или другой клиент.
2. До изменения открой актуальную страницу именно этого продукта/модели в официальной документации.
3. Не считай модель из текущего Codex-интерфейса тождественной последней API-модели.
4. Оценивай изменения на представительных задачах; для API-промпта храни версию рядом с кодом и используй fixtures/evals там, где это оправдано.

Текущие рекомендации OpenAI меняются: руководство для семейства GPT-6 описывает более компактные инструкции и повторный аудит `AGENTS.md`, а отдельный Codex Prompting Guide документирует конкретный GPT-5 workflow. Эти страницы — ссылки для повторной проверки, а не постоянная настройка проекта.

## Проверки в этом проекте

- После правок JavaScript запускай `node --check game.js`.
- После изменений Canvas сверяй страницу в браузере: стартовый экран, рабочую сцену, читаемость спрайтов и активные состояния интерфейса.
- Не добавляй для игры API-вызовы, npm, сборку или удалённые игровые ассеты без отдельного требования.
- При заметном изменении обновляй `VERSION.md`, `CHANGELOG.md` и соответствующий документ `docs/`.
